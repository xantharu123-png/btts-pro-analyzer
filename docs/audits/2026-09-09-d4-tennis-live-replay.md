## Scope and outcome

The new known original publication is no longer an opaque, merely hashed
artifact during D4 verification. Every such original, including safe orphan
publications without a Shadow/B3 consumer, is checked against its actual A1
tour state, physical current native B1 receipt and causal whole-tour inventory.
The exact original prediction inputs and unrounded probabilities are replayed
using the known unchanged owning model. A linked B3 payload must refer to that
exact publication and reproduce the owning v3 features and comparison law.

The lightweight stored-card projection separately binds the exact original
parameters, markets and complete Event. That pure identity check does not read
model files, fit, recalculate a prediction, fetch data or activate an effect.

No new wager, market ban, price filter, DB schema, native identity inference,
injury coefficient, historical row rewrite, updater change or Cricket path.
No old C2/C3/C4 replay or old Tennis v2 behavior is relabelled or disabled.

## Actual boundaries

- `_verify_artifact_types` recognizes exactly `tennis-live-winner-original-v1`
  and validates its closed publication shape/clock. The subsequent mandatory
  `verify_live_originals` runs after the existing full observation decoder in
  the same caller-held sealed-image transaction. Unreferenced originals receive
  the same checks. The early type branch alone is never a successful proof.
- The referenced `tennis-tour-state` must exist, match the exact tour, have
  actually been published before the original decision, and decode as the
  owning immutable state. Model build/training cutoffs remain enforced.
- Six recorded original source-file digests must correspond to the currently
  supported owning implementation. Only raw/LF/CRLF byte equivalence is allowed;
  no AST/text substitution, unknown recipe, permissive flag or new code approval.
  A future change to one of those model files requires explicit compatible
  historical replay before D4 will release these old originals. This is a
  continuity contract, not proof of dependency versions or executed bytecode.
- The actual native status must be the unique latest target revision at the
  original cutoff, scheduled, issue-free and exactly equal in tour, ordered
  players, competition, schedule, receipt time and competition revision. A
  newer predecision cancellation/changed input cannot be hidden by omitting it
  from the B3 reference list. A genuinely postdecision record does not rewrite
  an earlier decision.
- The real `predict_match` is called only in this explicit offline D4 audit,
  with the exact recorded inputs, actual decoded state and original cutoff,
  no odds and an empty optional descriptive workload list. Its same-call
  unrounded original callback must match exactly. There is no model refit.
  Decoded states and complete tour selections are reused across originals.
- `select_tennis_observations` is extracted from the unchanged latter half of
  the existing B1 reader. The live reader still decodes all rows before scope
  pruning and uses the same selection/sort/validation. D4 supplies already
  decoded rows from its own image; it never opens the live path through B1.
  Opaque unopened D2 final receipts are not decoded or promoted by this route.
- B3 derives the original artifact digest from the exact embedded origin,
  requires it in the verified original inventory, requires the v3 feature
  version, and compares the entire actual causal tour receipt list and feature
  vector before the existing numerical transport replay. The `used` law still
  follows the existing B3 approval rule, not a new publication flag.
- `_feature_binding` invokes the pure owning original validator whenever the
  explicit live version OR reference kind is present, including read-time
  projections. Removing/changing only one marker cannot bypass that binding.

## What remains unproved

Recorded model name keys are reproducible inputs, not a new native historical
player-ID/state resolver. Native source completeness, real court/environment
qualification and an empirically approved fatigue/injury effect are not created
by reading a saved original. The existing named limitations
`d1-original-replay-context-unavailable` and
`d3-owning-source-feature-replay-unavailable` remain explicit.
`empirical_approval_verified` stays exactly false and the actual live fixture
reports `transport_only`. No unknown-code/schema limitation was whitelisted in
the privileged updater. Its accepted limited-status policy is a separate review.

The D4 image contains the context store, not Shadow. The independently reviewed
producer/Shadow transaction enforces original publication <= actual append;
this packet does not claim to rejoin every production Shadow database.
