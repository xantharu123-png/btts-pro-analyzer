# D3 owning worker and transport rulings — 9 September 2026

These narrow implementation decisions answer the read-only D3 preflight. They
do not change the approved empirical acceptance, baseline visibility, Cricket,
source entitlement, 15K or immutable-history contracts. D3 is not completed by
writing this document. Existing B1/B3 and owning sport contracts remain primary.

## Closed immutable transport

Use the existing A1 database/B3 table. A new B3 payload is explicitly versioned
`context-worker-snapshot-v1` and contains the full original Event, BaseDistribution
and FeatureVector, the exact sorted unique input observation and preprocessing
references, the inspected effect/approval identities, and the exact ContextResult.
Its canonical decision is the original Base cutoff, equal to the Feature cutoff.
Its B3 key binds all those original inputs through the existing snapshot_key;
include every input receipt, not merely the nonempty usable feature refs.
The B3 context-ref set additionally contains one explicit input-descriptor
digest over transport kind and the two separately typed reference lists. This
is NOT a source receipt: it prevents changing a receipt into a preprocessing
ref with the same union, and prevents colliding with old bare B3 payload keys.
Both referenced canonical effect/approval envelopes are retained for pure
read-time identity checks and must match the actual A1/D2 resolutions at the
worker/runtime boundary; embedding them never grants source/approval authority.

The payload is not a free-form forecast or a new approval envelope. Validate all
closed shapes, canonical bytes, exact event/cutoff/market orientation, parameter
and result bindings. The owning pure sport comparison must be replayed from the
original parameters and actual resolved effect, then B3 selection replayed. Do
not accept a caller-supplied comparison probability, free callback, `verified`
flag or price field as evidence. A missing/inapplicable effect keeps exact base;
a numerical model failure is separately represented; identity corruption raises.

A compact consumer reference binds the B3 key AND its existing key-bound payload
digest. Projection verifies that reference and selects an exact canonical market
from `used_markets`. It carries full used parameters and the selected market,
never a probability reconstructed from rounded card text. Two consumers may
select different coherent markets, not different underlying distributions.

The worker/audit validation may replay an owning Base reference recipe. The
consumer read must NOT: the C2 reference validator reconstructs its Ridge fit.
Read projection therefore checks the already published key-bound payload,
closed scalar shapes, complete input/feature/result identities and exact
selected values without replaying that fit or the comparison. This is a
deliberately weaker read-only identity boundary, never source/approval proof.
Full validation and numerical/source replay remain mandatory before publication
and in the owning runtime audit. A lightweight check cannot publish new evidence.

The first pure transport packet connects only B5 football roster-v2, B7 Tennis
winner/serve performed-load-v2 and C2 basketball rotation-v1. C2 v1 has no named
preprocessing contract and rejects a nonempty preprocessing-reference list.
C1 weather/load, C3 and C4 require their own explicit version adapters; none is
silently inferred from parameter shape. Unsupported adapters are not certified.

## Source and approval verification are separate, mandatory owning boundaries

Pure transport replay proves deterministic input/result identity, not that the
inputs came from a real provider or were historically knowable. Worker assembly
loads actual A1/B1 bytes and builds features from the complete causal owning
receipt pool before publishing. D4 resolves those same refs from its real
read-only inventory and verifies the feature replay and source/recipe capabilities;
an unsupported source/base replay remains an explicit limitation, not success.
Do not silently upgrade a structural hash test into a causal or empirical proof.

Basketball MUST use its owning cross-schedule appearance reader. Generic B1's
current exact-schedule selector stays unchanged; its known wrong-path F5 probes
remain negative integration evidence. Other sports must retain the whole native
participant/status lineage required by their owning feature resolver, without
reviving obsolete values. Source capture reuses already budgeted actual receipts.

D2 resolves empirical approval outside the B3 CPU callback. Its historical
`verify_approval(connection, approval_hash)` is read-only and replays the actual
dataset/cases/fit/report; live `approved_effect` additionally checks the current
manifest and the original decision cutoff/scope. Cache this verification within
one worker batch, not indefinitely or by price/tab. No substitute handbuilt
approval or `passed=True` is accepted by worker/runtime verification.

## Live original bases and staged support

Do not silently replace the existing separately calibrated football probabilities
with the D1 raw-goal baseline. Capture full unrounded original values before card
projection; if their owning Base version/source contract is not supported, retain
the legacy output without a fabricated shared-context certification. A raw-goal
approval cannot be transferred to that calibrated legacy version. The new raw
version can be evaluated independently under D2, not disguised as byte-parity.

Tennis winner and serve remain separate original families. No native identity
from player names, no holds from winner-p and no causal state replay without its
owning native resolver. C2/C3/C4 exports retain exact original values. Unknown
reference/source features stay unavailable; missing context does not remove an
otherwise available baseline. C1 workload/weather are distinct existing feature
versions, not automatically members of the B5 roster-v2 effect contract.

## Once-only boundary, consumers and public text

Prepare one event/family case per shared worker batch and pass the same immutable
reference to both consumers. Count provider/base/feature work separately from the
B3 comparison callback. Existing B3 cross-process locking only proves the latter;
do not claim globally once-only upstream work without an owning tested boundary.
Cover automatic and all existing manual worker entry points. Render, filter,
tab-switch and price-only actions consume immutable data and initiate no modeling.

New optional fields in ModelSignal/EventModelSnapshot use a closed transport
contract. Absent legacy fields remain absent, not serialized as new null values.
Update strict domain/store/UI readers together and retain old IDs/hash bytes.
New context versions must not inherit old strict/RELEASED/15K approvals. Existing
price-blind coherence/diversity and revision-bound manual price rules remain.

Public context copy uses an owning explicit feature grouping, never guessed
technical feature-name substrings. Known data without approved numerical use
says `Wirkung offen`; missing data is not known/healthy/zero. Only applied factors
say `eingerechnet`. Overall zero is not attributed as each individual factor's
zero effect. Short public text stays separate from admin errors and artifacts.
No new nested primary card container. Actual browser proof remains required.
