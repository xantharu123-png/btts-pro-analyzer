## Fixed provenance and completion

1. `_validate_all_with_tennis(artifacts)` enters one shared complete physical
   implementation. Preparation is available only for the exact inventory and
   exact `VerifiedArtifactMapping` classes, same connection and generation.
   Dicts, subclasses, foreign mappings and previously completed physical passes
   get ordinary physical validation with no prepared cache. The latter have no
   saved source checks and follow the existing postphysical preparation route.
2. Planning walks every real artifact and validates every original publication,
   including unreferenced/excess-query publications. It reads that artifact's
   persisted creation timestamp from the same connection, never a supplied
   cutoff/created-at dictionary. Missing maximum reservations cancel preparation
   rather than silently preparing only one tour. There are at most two maxima.
3. The new complete unfiltered receipt query alone adds
   `ORDER BY r.observed_at,r.digest`. It retains the original LEFT JOIN and every
   receipt; it adds no persistent index, table or schema mutation. Every known
   Tennis row through the union maximum receives the source tail before tour
   retention. Retention is restricted to the row's own tour maximum, not to an
   event, participant, latest row or retained original query.
4. The same non-yielding owning row frame invokes the real physical decoder,
   the complete shared source tail and only then fixed evidence construction.
   Neither a caller-provided row, callback, flag, direct cache store nor a
   successful ordinary physical pass can execute the completion transition.
5. Only after content/receipts/orphans/final stamp succeed does that actual
   owning operation transition its newly constructed cache from preproof to
   the exact completed inventory stamp. The existing global proof checks were
   not relaxed. It independently decodes and full-cold-validates every pending
   encoding, folds all retained queries, then obtains exact new entry serials.
6. Only the still-running completed physical/source owner attaches owned
   completeness markers to those sealed serials. The row-seal helper itself
   grants no aggregate completeness. Marker-fit or reentrant cancellation clears
   every tour; no partial other-tour cache is returned. Runtime handoff requires
   the exact artifact-map pin and current owned entry serials; a supplied public
   cache/subset/row seal cannot bypass complete preparation or source coverage.
7. Before/after row, seal, fold, marker and final/empty boundaries still inspect
   the actual transaction, changes, main/temp schemas and proof. Same-key
   replacement loses seals/owned markers as before. A recursive physical pass
   fails closed instead of constructing a second pending pool.

## Error precedence, fallback and admission

Planning catches only deterministic `ContextContractError` and
`ArtifactIntegrityError` in its short-lived optional planning frame. Source
deferral catches only `ContextContractError` around the source tail, never the
physical decoder. Both return cancellation with no stored exception, traceback
or args. The caller releases pending/planning state after those frames and their
exception contexts have ended, then completes physical validation. Existing
postphysical planning/full cold selection subsequently reproduces real domain
rejection. A malformed early source/publication cannot hide a later corrupt
receipt or orphan. No domain failure becomes accepted absence.

Unexpected exceptions, SQLite/closure/transaction/schema failures, interrupts
and `MemoryError` propagate fail-closed with cleanup. The new tests exercise
source, encoding, independent seal and fold mutations, final/empty proof
revocation, plus ordinary full fallback after source cancellation. Pool pressure,
zero queries, missing originals, an unreservable maximum, oversized rows/bases,
and one byte below marker fit are optional fallback conditions, not new input
rejections. Whole-prefix history admission remains 256MiB and precedes actual
original native absence/ambiguity; original model and source replay are unchanged.

## Accounting and reference lifetime

There is one existing `_bytes + _pending_bytes` budget, 64MiB in production.
Both tours' pending encodings live only in that cache's pending containers;
there is no decoded full basis, spill list, second encoding, key sort pool or
model/result cache. Every appended encoding is charged before another row can
accumulate. Query reservations remain bounded by 30; both pending tour slots are
visible in diagnostics, and total slots are at most 32. Existing 128-byte tour
planning reservations remain; the new containers/counters/artifact owner pin
reserve an additional `256 * tour_count + 128` bytes inside the same budget.
Owned markers retain their actual serialized-key/serial charge.

Queries are lower priority than a fitting pending basis. If the entire plan,
complete bases and markers cannot fit, all optional state is released and the
old route is used. The seal decodes one pending row, full-cold-validates/folds it
and ends that worker frame before publication/cancellation. Tuple freezing moves
references to the same bytes; the popped pending list's temporary ends before
the pending-to-retained accounting transition, without copying encoded content.
The content phase releases its final decoded/raw work before pending rows begin.

The new tests observe actual weakrefs to decoded rows and query drafts and actual
refcounts of retained byte objects and 4096-character query keys. At independent
seal entry all decoded physical rows have died; an observed encoded byte object
has exactly one cache owner while pending, exactly one after transfer, and none
after eviction. Source worker locals are cleared in `finally` before cancellation.
For query-binding pressure, the complete short-lived binding helper retains the
old charge until its tuple iterator, dropped keys and query locals die; only its
returned integer release count is uncharged by the caller. A genuine serial
reservation/marker-fit perturbation verifies both draft weakrefs dead and keys
at probe-only refcount before uncharge. Root's WIP preflight identified the
initial same-loop key-uncharge hazard; it was corrected and regression-tested.

No retained exception/traceback is used as cancellation state. Reentrant stores
set cancellation before dropping drafts or entering another pending build; they
cannot take the outer pool's charge or preserve replacement authority.
